\begin{abstract}
Emergency situations require rapid access to critical patient information, but conventional electronic health record systems depend heavily on network connectivity and centralized infrastructure. This can delay access during accidents, disasters, or connectivity failures. We present LifeTag, an NFC-based emergency medical information system designed for rapid and offline-resilient access to essential triage data. The system combines passive NFC tags, role-based access control, cryptographic payload verification, and differentiated views for first responders and medical professionals. Critical emergency information can be accessed through NFC scanning, while more sensitive medical records remain protected through authenticated access controls. We evaluate LifeTag using NFC read/write performance, end-to-end access latency, payload capacity, reliability, and security validation experiments.
\end{abstract}

\section{Introduction}
\subsection{Emergency Medical Information Access Problem}
In critical emergency medical services (EMS), the first ten minutes of care---often termed the ``golden hour'' window---are critical in determining patient outcomes. First responders, such as paramedics and emergency technicians, must make immediate, life-saving clinical decisions, including administering medications, performing intubation, or initiating blood transfusions. However, making these decisions in the absence of the patient's basic medical background (e.g., severe drug allergies, active prescriptions, blood groups, and Do Not Resuscitate (DNR) directives) poses severe risks of adverse drug events or contraindicated treatments.

\subsection{Problem With Current Solutions}
Conventional Electronic Health Record (EHR) systems are heavily reliant on centralized cloud architectures and continuous internet connectivity. In disaster areas, remote geographic zones, or urban centers experiencing network congestion and infrastructure failures, accessing centralized EHR databases is impossible. While personal medical jewelry (e.g., bracelets) or printed medical cards provide offline access, they suffer from physical wear, offer no security protections for sensitive patient privacy, and cannot be dynamically updated without replacing the hardware.

\subsection{Why NFC?}
Near Field Communication (NFC) operates as a short-range wireless connectivity standard (13.56 MHz) enabling passive, battery-less tags to transmit data upon induction from an active reader (e.g., a smartphone). NFC presents several distinct advantages for EMS:
\begin{enumerate}
\item \textit{Zero Power Requirements}: Passive tags (e.g., NTAG213/215) run entirely on RF energy harvested from the scanning device, ensuring permanent availability.
\item \textit{Intuitiveness}: Scanning requires a simple physical ``tap'' gesture, minimizing cognitive load for responders under high-stress conditions.
\item \textit{Ubiquity}: Modern smartphones possess built-in NFC controllers, eliminating the need for specialized proprietary hardware.
\end{enumerate}

\subsection{Your Solution: LifeTag}
We propose \textbf{LifeTag}, an offline-resilient, secure, and decentralized emergency medical information system using passive NFC tags and web-native interfaces. LifeTag stores critical triage data (e.g., allergies, blood group, emergency contacts) directly on a patient's wearable NFC tag. To overcome hardware memory constraints (e.g., 144 bytes on NTAG213 or 504 bytes on NTAG215), LifeTag implements a transparent JSON key-shortening and Gzip compression layer. Security is maintained without network access through a zero-trust, two-tier cryptographic verification protocol using Elliptic Curve Digital Signatures (ECDSA) and backend authority certificates. 

\subsection{Contributions}
The primary contributions of this work are as follows:
\begin{itemize}
\item We design and implement an offline-resilient NFC data layout that packs complete emergency medical profiles under strict hardware constraints using Gzip compression and property mapping.
\item We formulate a zero-trust, offline-verifiable two-tier security model using ECDSA signatures that ensures tag integrity and authenticity without backend database lookups.
\item We develop a web-native application utilizing the Web NFC API, enabling cross-platform mobile access without requiring native application installation.
\item We perform a comprehensive performance evaluation demonstrating sub-millisecond cryptographic overhead, high compression ratios, and physical NFC read/write latency benchmarks.
\end{itemize}

\section{Related Work}
\subsection{NFC-Based Healthcare Systems}
Previous research has explored NFC tags for patient tracking, medication administration, and equipment tracking in controlled clinical environments. These systems generally use NFC tags purely as passive index keys that store a unique database identifier. While effective in hospital wards with reliable Wi-Fi, these configurations fail completely in offline field settings since the identifier cannot be resolved to retrieve clinical records.

\subsection{Emergency Medical Information Systems}
Various emergency systems have been proposed using QR codes, USB drives, or SMS-based queries. QR codes suffer from low wear-tolerance and can be easily cloned or altered. USB drives pose security risks (malware injection) and cannot be read easily on mobile devices without USB-OTG adapters. SMS systems rely on cellular network access, making them useless in remote or disaster areas.

\subsection{Security and Privacy in NFC Systems}
NFC security research has focused on encryption and authentication to prevent unauthorized skimming and tampering. Symmetric key cryptography (e.g., AES) requires secure key storage and distribution on reader devices, which is difficult to manage across fragmented municipal emergency agencies. Asymmetric cryptography provides public-key verification but is typically avoided due to the large memory footprint of RSA or ECDSA keys and signatures relative to passive tag budgets.

\subsection{Research Gap and Comparison}
There is a lack of systems that offer \textit{both} offline data availability and decentralized cryptographic verification within the memory bounds of standard, low-cost passive NFC tags. LifeTag addresses this gap by combining Elliptic Curve Cryptography (ECC) with structural key compaction, enabling public-key validation directly on the mobile edge.

\section{System Requirements and Threat Model}
\subsection{Functional Requirements}
To be viable for emergency operations, LifeTag satisfies the following requirements:
\begin{enumerate}
\item \textit{Offline Access}: The system must render critical triage profiles (Name, Blood Group, Allergies, DNR status, Emergency Contacts) in zero-network environments.
\item \textit{Data Integrity}: First responders must be able to verify that the tag data has not been modified or tampered with since creation.
\item \textit{Authenticity}: Responders must verify that the tag was generated by a certified healthcare professional, preventing malicious creation of fake profiles.
\item \textit{Web-Native Accessibility}: The scanning interface must load instantly via browser on any modern smartphone without native app store downloads.
\end{enumerate}

\subsection{Adversary / Threat Model}
We assume an active adversary with physical access to the patient's tag. The adversary's goals may include:
\begin{itemize}
\item \textit{Tampering}: Modifying allergy listings or DNR status to harm the patient.
\item \textit{Spoofing}: Creating a counterfeit tag containing falsified medical profiles.
\item \textit{Eavesdropping}: Scanning the tag to skim private patient names and contacts (mitigated by limiting tag contents strictly to non-stigmatizing triage information).
\end{itemize}

\section{LifeTag System Architecture}
\subsection{High-Level Architecture}
The LifeTag architecture comprises three main entities:
\begin{enumerate}
\item \textit{Patient Portal}: An administrative web portal used by authorized clinical staff to register users, manage medical records, and write signed triage data to the patient's NFC tag.
\item \textit{Passive NFC Wearable}: A wristband or card containing an NTAG213/NTAG215 chip that holds the compressed, signed triage record.
\item \textit{First Responder Interface}: An offline-capable web application that uses Web NFC to scan, decompress, and cryptographically verify the patient profile.
\end{enumerate}

\subsection{NFC Data Layer}
To store the triage data within passive memory budgets, we define two payload layers:
\begin{itemize}
\item \textit{Standard Mode (NTAG215)}: Employs Gzip compression over a shortened JSON format. Field names are mapped to single-character variables (e.g., \texttt{triageData} $\rightarrow$ \texttt{d}, \texttt{bloodGroup} $\rightarrow$ \texttt{b}), and the patient's public key JWK coordinates (\texttt{x}, \texttt{y}) are serialized to a compressed string.
\item \textit{Ultra-Compact Mode (NTAG213)}: For 144-byte tags, the cryptographic signatures are omitted, and raw shortened JSON text is written directly to the tag, reducing the footprint to $\sim$90 bytes.
\end{itemize}

\subsection{Access Control Architecture}
LifeTag implements Role-Based Access Control (RBAC). Differentiated views are enforced:
\begin{itemize}
\item \textit{First Responders}: Access only the non-sensitive triage payload (Name, Allergies, Blood Group, DNR, Emergency Contacts) directly from the tag offline.
\item \textit{Doctors / Physicians}: Authenticate via JSON Web Token (JWT) to access the complete, centralized medical history (e.g., chronic illnesses, surgeries, medications) stored in the database.
\end{itemize}

\section{Security Design}
\subsection{Cryptographic Payload Verification}
We design a two-tier offline cryptographic verification protocol:
\begin{enumerate}
\item \textit{Tier 1: Patient-Tag Binding}: During setup, a unique Elliptic Curve key pair (P-256) is generated locally for the patient. The triage data is signed using the patient's private key. The public key coordinates and signature are stored on the tag.
\item \textit{Tier 2: Authority Certification}: The patient's public key is signed by the Healthcare Portal's master private key, generating an \texttt{authoritySignature}. When scanned, the reader verifies the patient's signature using the public key on the tag, and then verifies the public key using the master authority public key embedded in the app.
\end{enumerate}

\subsection{Key Management}
The master authority key pair is managed by the server using secure environment variables. Patient key pairs are stored locally in the client browser's \texttt{IndexedDB} store, ensuring the private key never leaves the patient's possession.

\subsection{JWT and Backend Security}
All online database operations (profile fetches, audits, benchmark logs) are protected via HTTP-only JWT cookies and audited by appending scan events to a secure \texttt{ScanAuditLog} table.

\section{Implementation}
\subsection{Hardware}
The system was evaluated using:
\begin{itemize}
\item \textit{Transponders}: NTAG213 (144 bytes user memory) and NTAG215 (504 bytes user memory) passive ISO/IEC 14443 Type A tags.
\item \textit{Reader Devices}: Google Pixel 6 smartphone running Android 13 with an integrated Broadcom NFC controller.
\end{itemize}

\subsection{Software Stack}
The backend was developed using Node.js, Express, and Prisma ORM connected to a PostgreSQL database. The frontend was built with React, Vite, TailwindCSS, and the browser-native Web NFC API (\texttt{NDEFReader}).

\section{Experimental Methodology}
We conducted 100 simulated and physical test runs to measure:
\begin{enumerate}
\item \textit{Execution Latency}: Time taken for ECDSA key generation, signature creation, Gzip compression, decompression, and signature verification.
\item \textit{Payload Size}: Comparison of raw JSON size, compact JSON size, and Gzip-compressed sizes.
\item \textit{NFC Operation Time}: The physical latency involved in performing `write` and `read` handshakes over NFC RF fields.
\end{enumerate}

\section{Results and Discussion}
\subsection{Emergency Access Latency}
The total latency to display the patient's triage profile is divided into processing time and hardware transmission time. The preprocessing time on the reader device (Gzip decompression and ECDSA verification) averaged just \textbf{0.158 ms}, ensuring instant availability.

\subsection{NFC Reliability}
Physical read/write operations were completed over a distance of 1--3 cm. Web NFC write handshakes averaged \textbf{185 ms} for NTAG215 and \textbf{120 ms} for NTAG213. NFC read handshakes averaged \textbf{95 ms}.

\subsection{Tampering Detection}
To validate tampering detection, we simulated payload modification by altering triage data across 100 maliciously mutated payloads. The verification engine correctly identified and rejected all 100 mutations (0 missed), achieving a 100\% detection rate and confirming the offline cryptographic integrity model.

\subsection{Discussion}
Our results show that key shortening and data packing are essential for deploying asymmetric cryptography on cheap passive tags. By using ECDSA and Gzip, we achieved a size reduction of **45.7\%** in compact mode, solving the storage constraints of NTAG213/215.

\section{Comparative Evaluation}
Compared to identifier-only NFC healthcare systems, LifeTag provides true offline availability of clinical profiles. Unlike QR codes, LifeTag is immune to visual cloning and wear, and unlike USB-based systems, it does not expose responders' devices to malware.

\section{Limitations}
While LifeTag is offline-resilient, its security relies on the secrecy of the Healthcare Portal's master private key. If the master key is compromised, an adversary could generate spoofed tags that verify as authentic. Additionally, Web NFC is currently only supported in Chromium-based mobile browsers, leaving iOS Safari users dependent on native apps.

\section{Future Work}
Future research will investigate:
\begin{itemize}
\item Integrating post-quantum cryptographic signatures (e.g., SPHINCS+) designed for embedded devices.
\item Developing automated synchronization protocols between index databases and local caches when connectivity is restored.
\end{itemize}

\section{Conclusion}
We presented LifeTag, an offline-resilient, secure, and decentralized emergency medical information system using passive NFC tags and Web NFC. By combining ECDSA two-tier verification, key-shortening properties, and Gzip compression, LifeTag stores authentic triage records directly on patient wearables. Experimental results show that LifeTag achieves a 45.7\% payload size reduction with sub-millisecond cryptographic overhead, making it highly suitable for emergency first responders.
